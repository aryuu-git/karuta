## 📖 游戏规则

### 游戏概述

歌牌大乱斗是一款**多人实时抢牌游戏**。房主选择一个牌组，系统依次播放牌组里每首歌曲的音频，玩家需要快速找到并点击棋盘上对应的那张牌。
听音辨牌，手速决定胜负！

### 🃏 牌库与牌组

#### 牌库

牌库是独立于牌组的卡牌仓库。每张牌包含：

| 内容 | 说明 |
|------|------|
| **封面图** | 牌的正面图片（必须上传，游戏中展示） |
| **歌曲** | 可绑定**多首**音频（至少 1 首），游戏中随机播放 |
| **牌名** | 角色/作品名，用于牌库管理 |
| **作品名** | 所属作品（如"进击的巨人"），用于筛选 |
| **标签** | 自定义标签，用于筛选 |
| **播放提示** | 每首歌可设独立提示（歌维度），播放时显示 |

- 牌可设为**共享**（默认），出现在公共牌库供所有人使用
- 同一张牌可以被多个牌组引用

#### 牌组

牌组是游戏的素材集合，通过从牌库中**选牌**组建：

- 从个人牌库或公共牌库中选牌添加到牌组
- 同一张牌可出现在多个牌组中（引用关系，不是复制）
- 从牌组移除牌 = 解除引用，不会删除牌本身

#### 牌组共享（三级）

| 等级 | 说明 |
|------|------|
| 🔒 私有 | 仅自己可见和游玩 |
| 🎮 可使用 | 他人可选此牌组建房游玩，但不能改内容 |
| ✏️ 可编辑 | 他人可对此牌组做编辑（分"仅添加"和"完全编辑"两种粒度） |

支持**一键复制牌组**，基于他人公开牌组创建自己的变体版本。

#### 多音频牌（堆叠牌）

一张牌可以绑定多首歌曲：

- 游戏中所有歌曲**全局随机打散**播放
- 棋盘上该牌显示**堆叠效果 + ×N 角标**
- 每抢到一次或无人抢时消耗一层
- 所有层耗尽后牌消失
- 多音频牌相当于"分值更高的牌"（N 层 = 最多贡献 N 分）

#### 支持的格式
- **音频**：mp3、wav、m4a、flac、ogg、aac（单文件 ≤ 20MB）
- **封面图**：jpg、png、webp（单文件 ≤ 5MB）

#### 音频上传处理

上传音频时可选：
- **压缩**（默认开启）：转为 MP3 128kbps，减小体积
- **裁剪前 30s**：只保留前 30 秒
- **随机裁剪 30s**：从随机位置截取 30 秒

处理在浏览器端完成，上传的是处理后的小文件。

### 🏯 房间与游戏模式

#### 创建房间
1. 进入首页，点击"创建房间"
2. 选择一个牌组（必须至少有 1 张牌）
3. 设置**朗读间隔**（3 ~ 30 秒）：音频播放完毕后，留给玩家抢牌的缓冲时间
4. 选择游戏模式
5. 可选开启**模糊牌面**（增加辨识难度）
6. 创建后获得 6 位**邀请码**，分享给朋友

#### 加入房间
- 在首页"战场大厅"找到招募中的房间，直接点击加入
- 或输入邀请码加入
- **激战中的房间不可加入**（只有招募中的房间开放加入）

### 🎮 游戏模式

#### 模式一：自动模式

**适合多人在线一起玩**

1. 所有人加入房间后，房主点击**「全员集合！开战！」**
2. 游戏开始前有 **3-2-1 倒计时**
3. 系统从牌组中**随机打散所有歌曲**开始播放
4. 棋盘上展示本局所有牌的封面，**不显示任何文字**（需要靠听歌识牌）
5. 音频播放完毕后进入**缓冲期**（即设定的朗读间隔时长），缓冲期内仍可抢牌
6. 缓冲期结束进入下一首，循环直到所有歌曲都结束
7. 所有歌曲结束后自动进入结算页

#### 模式二：裁判模式

**适合线下聚会，由一人主持游戏**

1. 房主作为**裁判**，其他玩家参与抢牌
2. 裁判看到的是全部牌的列表，可以**任意选择播放哪首**
3. 裁判点击一张牌 → 音频广播给所有玩家 → 玩家抢牌
4. 一首结束后，界面提示裁判选择下一首
5. 裁判不参与抢牌、不计分

### 🎭 模糊牌面（可选）

创建房间时可开启**模糊牌面**模式：

| 难度 | 效果 |
|------|------|
| 简单 | 轻微遮挡 1/4 面积 |
| 普通 | 遮挡 1/2 + 轻微模糊 |
| 困难 | 遮挡 3/4 + 重度模糊/马赛克 |

- 6 种随机遮罩效果（裁切/对角/模糊/马赛克/条纹/聚光灯）
- 所有玩家看到的遮罩效果完全一致（服务端种子保证）
- 牌被抢完后揭示完整封面

### ⚡ 抢牌规则

#### 基本流程
1. 音频开始播放
2. **任意时刻**均可点击棋盘上的牌（整个播放过程中都可以抢）
3. 音频结束后进入缓冲期，缓冲期内仍然可以抢牌
4. 缓冲期结束，本首结束，进入下一首

#### 判定规则
服务端以**消息到达时间**为权威判定依据，完全防止客户端作弊。

| 结果 | 条件 | 得分变化 |
|------|------|---------|
| ✅ 抢牌成功 | 第一个点击当前播放的牌 | **+1 分** |
| ❌ 抢错（已被抢） | 点击了当前牌，但已被别人先抢 | **-1 分**，本首禁止继续抢牌 |
| ❌ 抢错（错误的牌） | 点击了不是当前播放的牌 | **-1 分**，本首禁止继续抢牌 |
| 🚫 本首出局 | 本首已抢错过一次 | 点击无效，只能观望 |

> 分数可以为负数！抢错次数多会导致负分。

#### 全员出局
- 若本首所有在线玩家都已抢错，游戏自动结束本首，进入下一首
- 提示：「全员出局！本首自动结束」

#### 无人抢牌
- 若音频播完 + 缓冲期结束均无人抢牌，本首自动结束
- 该牌**消耗一层**但不计入任何人得分

### 📊 计分规则

| 情况 | 分值 |
|------|------|
| 成功抢牌 | +1 |
| 抢错（任意原因） | -1 |
| 无人抢 | 0 |

- 分数**可以为负数**
- 每首歌开始时，本首的禁止状态**重置**（下一首所有人都可以重新抢）
- 多音频牌的每首歌独立计分

### 🎯 棋盘说明

- 棋盘展示本局所有牌的**封面图**
- **不显示文字**（歌名、歌词等），需要靠听歌识牌
- 牌的显示顺序在开局时**随机打乱**，且每个玩家的顺序相同
- 多音频牌显示堆叠效果和剩余层数角标（×N）
- 牌所有层耗尽后缩小显示在棋盘底部
- 正在播放的牌**不会高亮**（防止作弊）
- 如果开启了模糊牌面，封面会被遮罩处理

### ⏸ 暂停与继续

- 仅**房主**可以暂停和继续游戏（自动模式）
- 暂停时音频暂停，计时器冻结，玩家无法抢牌
- 继续后音频恢复，计时器从暂停处继续倒计时

### 🏆 结算

所有歌曲打完后进入结算页：
- 按得分**从高到低**排列
- 显示 🥇🥈🥉 前三名特效
- 每个玩家展示抢到的所有卡片（每首歌独立展示）
- 同一封面可能出现多次（多音频牌被不同人抢了不同歌）
- 可选择「再战一次」或「回家休息」

### 👑 特殊权限

**房主权限**
- 开始游戏（waiting 状态）
- 暂停/继续游戏
- 解散战场（强制结束房间）
- 裁判模式下选择每一首牌播放

**管理员（aryuu）**
- 可在**首页战场大厅**强制结束任意激战中的房间
- 可在**游戏内**通过控制栏强制结束当前对局

### ❓ 常见问题

**Q：音频播放很长，什么时候可以抢？**
A：整个音频播放过程中随时可以抢，不受间隔时间限制。间隔时间是音频播完后的缓冲等待期。

**Q：一张牌有多首歌，每首歌都要抢吗？**
A：是的。多音频牌的每首歌是独立的一轮，全局随机打散。同一张封面可能在游戏中出现多次。

**Q：模糊牌面遮住了封面看不清怎么办？**
A：这就是难度所在！靠听力判断歌曲对应哪张牌，而非靠封面辨认。

**Q：点了一张牌没有反应？**
A：可能是当前没有牌在播放（等待状态），或你本首已经抢错被禁止。

**Q：我的分数变成负数了？**
A：抢错次数过多会扣分，分数可以为负。

**Q：为什么棋盘上的牌没有文字？**
A：故意设计的！需要通过听音频来判断是哪张牌，这才是游戏的核心玩法。

**Q：可以中途加入游戏吗？**
A：不可以。激战中的房间禁止新玩家加入，只有「招募中」状态的房间才能加入。

## 功能特性

- 账号系统（注册/登录，JWT 鉴权）
- **独立牌库**：牌与牌组解耦，支持复用、共享、筛选
- **多音频牌**：一张牌绑定多首歌，堆叠展示
- **音频处理**：上传时可选压缩/裁剪（前端 ffmpeg.wasm）
- **三级共享**：牌组支持私有/可使用/可编辑 + 一键复制
- **模糊牌面**：6 种 CSS 遮罩效果 × 3 档难度
- **COS 对象存储**：文件存储支持腾讯云 COS（可选，环境变量开关）
- 实时多人对战（WebSocket，10 人+房间）
- 两种游戏模式（自动/裁判）
- 服务端权威抢牌判定（防作弊）
- 抢对/抢错实时音效 + 全房公告
- 响应式设计，支持桌面和手机

## 本地开发启动

### 需要准备

- **Go 1.21+**（[下载](https://golang.org/dl/)）
- **Node.js 18+** + npm（[下载](https://nodejs.org/)）

### 启动步骤

**方式一：双击启动脚本（Windows）**

```
双击 dev.bat
```

脚本会自动：
1. 关闭占用 8080/5173 端口的进程
2. 编译后端
3. 编译前端
4. 启动后端（:8080）和前端开发服务器（:5173）

**方式二：手动启动**

```bash
# 终端1 — 后端
cd karuta
go run ./cmd/server

# 终端2 — 前端
cd karuta/frontend
npm install    # 首次需要
npm run dev
```

打开浏览器访问 **http://localhost:5173**

### 环境变量

| 变量 | 默认值 | 说明 |
|------|--------|------|
| PORT | 8080 | 后端监听端口 |
| JWT_SECRET | karuta-secret-key | JWT 签名密钥 |
| DB_PATH | ./karuta.db | SQLite 数据库文件路径 |
| UPLOAD_DIR | ./uploads | 音频/封面文件存储目录 |
| COS_ENABLED | (空) | 设为 `true` 启用腾讯云 COS |
| COS_SECRET_ID | — | 腾讯云 SecretId |
| COS_SECRET_KEY | — | 腾讯云 SecretKey |
| COS_BUCKET | karuta-1321249409 | COS Bucket 名称 |
| COS_REGION | ap-shanghai | COS 地域 |
| COS_CDN_DOMAIN | (空) | 可选 CDN 域名 |

## 注意事项

- 上传的音频文件最大 **20MB**，封面图最大 **5MB**
- 支持音频格式：mp3、wav、m4a、flac、ogg、aac
- 生产环境请修改 `JWT_SECRET` 环境变量
- `uploads/` 和 `karuta.db` 需要持久化存储
- WebSocket 需要 Nginx 配置正确的 `Upgrade` 头
- 首次从旧版升级需运行 `cmd/migrate-library` 迁移脚本
